# План A6–A8: изоляция мира, единые компоненты, сервисы, physics и abilities

Без обратной совместимости: тестовая игра переписывается на новом API после рефакторинга.
Порядок: A6a.1 → A6a.2 → A6b.1 → A6b.2a → A6b.2b → A6b.2c → A6c, затем A7 и A8 (не зависят друг от друга), затем A6d.

Правила для каждого PR:

- монорепо собирается и тесты зелёные после каждого PR: все потребители внутри репо (physics, abilities, game, фикстуры runtime, playground, integration) обновляются в том же PR;
- первым коммитом снимки экспортов, дальше CHANGELOG, мутанты, харнесс;
- формат сейва не меняется; если меняется — новый формат и регенерация голденов отдельным коммитом с объяснением в CHANGELOG.

## A6a. ecs: мир без глобального состояния

Два PR: первый маленький и механический, второй большой, но почти весь объём — правка тестов.

### A6a.1. Без работы при импорте

Статус: PR #83.

1. Убрать глобальный хост модулей мира. `save`/`restore`/`spawn`/`despawn`/`each` становятся функциями runtime: `saveWorld(world)`, `restoreWorld(world, bytes)`, `spawn(world, spec)`, `despawn(world, e)`, `each(world, Comp, fn)`. Удаляются `WorldModuleHost`, `setWorldModuleHost`, `requireWorldModules`, `phalanx-ecs/src/worldHost.ts`, `phalanx-runtime/src/world/host.ts` и вызов при импорте в `phalanx-runtime/src/index.ts`. Вызовы обновляются в ecs, runtime, game, integration и фикстурах.
2. Удаляется экспорт `globalEventBus` из ecs и game. Шина уже у каждого мира своя (`world.eventBus`), глобальная нигде не используется.
3. `"sideEffects"` ставится только после п. 1: иначе сборщик может выкинуть модуль, который при импорте подключает `save`/`spawn`, и это сломается только в продакшен-сборке.
   - ecs: `false`;
   - runtime: `["./dist/server/simWorker.js"]`. Воркер запускается по пути и никогда не импортируется.
4. Проверка `pnpm check:side-effects` (в CI): разбирает `src` каждого пакета с полем `sideEffects` и падает на любой инструкции верхнего уровня, кроме объявлений, импортов, экспортов и `const`/`let`. Внутри инициализатора, статического поля и блока, `extends`, декоратора, инициализатора enum и тела namespace вызов или `new` импортированного связывания, присваивание и немедленно вызванная функция — тоже работа при импорте. `new` и вызов функции, объявленной в том же файле, допустимы, только если тело этой функции само не делает работу при импорте: вызов локальной функции просматривается, в том числе цепочка `const f = () => g()`. Имя из деструктуризации импортированного значения (`const { setHost } = m`) — тоже импортированное связывание. Файлы из списка `sideEffects` пропускаются. Есть самотест. Проверка нашла цикл заполнения в `runtime/src/state/snapshot.ts`, он заменён на `Uint8Array.from`.
5. Тесты:
   - мир из чистого ecs: тесты ecs не импортируют runtime, а методов, которым он нужен, у `GameWorld` больше нет;
   - `saveWorld`/`restoreWorld`: существующие тесты переведены на функции, голдены те же;
   - `despawn` возвращает сущность из пула в пул (раньше не было покрыто).

Поведение не меняется, голдены те же.

### A6a.2. Счётчик id принадлежит миру

1. `entityIdCounter` из `Entity.ts` становится полем `EntityManager`. Удаляются `resetEntityIdCounter`, `getEntityIdCounter`, `setEntityIdCounter`, `nextEntityId`; сущности создаются только через мир, `new Entity()` уходит из публичного API. Конструктор `GameWorld` больше ничего не сбрасывает.
2. `world.createEntityWithId(id)` для восстановления. Секция `entities.ts` перестаёт двигать счётчик на `id - 1` и возвращать его обратно. Счётчик сохраняется и восстанавливается через мир, формат секции тот же.
3. Из `WorldScope` уходит подмена счётчика (подмена контекста SoA остаётся до A6b.2c).
4. Тесты:
   - два мира вперемешку: создать A, заспавнить, создать B, заспавнить, закрыть B, продолжить A. У каждого свои id; сейв A побайтно совпадает с сейвом A, прогнанного в одиночку;
   - восстановление через `createEntityWithId` даёт те же id и тот же следующий id;
   - голдены те же.

## A6b. ecs: единые компоненты

Четыре PR, чтобы каждый был обозрим. Старый путь живёт рядом с новым до A6b.2c, поэтому physics и abilities переводятся отдельно.

### A6b.1. Новый `defineComponent` рядом со старым

1. `defineComponent` переезжает из runtime в ecs (domain-пакеты импортируют его оттуда).
2. Три вида компонентов:
   - **SoA**: целочисленные поля (`i32`, `u32`, `u8`, `i64`), сохраняются автоматически, входят в `configHash`;
   - **объектный**: класс плюс `save`/`load`. Без них ошибка на `registerComponent`, а не при первом сейве. `save` обязан писать коллекции в детерминированном порядке: `Set`/`Map` сортируются по ключу (порядок вставки у разных клиентов может отличаться). Нужен хелпер для сортированной записи и тест;
   - **несохраняемый (transient)**: вид принят. Любые поля, включая `f32`/`f64` и объекты. Не попадает в сейв и `configHash`. Только для отображения: tick-системы могут его писать, но не принимают по нему решений. Страж: tick-система не ветвится по transient-компоненту; это проверяется хотя бы в dev-режиме. После `restoreWorld` его присутствие восстанавливает модуль-владелец в restore-хуке своей секции сейва (секции модулей есть с A3), значения берутся по умолчанию.
3. Доступ без статического контекста: `world.getComponent(e, Comp)`, `world.addComponent(e, Comp, values)`, `world.removeComponent(e, Comp)`. Мир передаётся явно, `defineComponent.create` статика не нужна.
4. Тесты: три вида, ошибка объектного без `save`/`load` при регистрации, детерминированный сейв `Set` при разном порядке вставки, transient не меняет байты сейва и `configHash`, dev-проверка не даёт tick-системе принять решение по transient-компоненту.

### A6b.2a. Перевод physics

1. `Transform`, `PhysicsBody` через `defineComponent` (SoA). `Interpolation` через `defineComponent` как transient: это образцы для сглаживания отрисовки, в сейв они не попадают.
2. `lastX/lastZ` (`f64`) удаляются из `PhysicsBody` без замены. Их пишут только `PhysicsSystem` и `CollisionSystem`, читает только геттер самого компонента; playground и integration их не используют. Float-позицию для отрисовки дают `Transform` и `Interpolation`. Обновить комментарии в `phalanx-physics/src/save/broadphase.ts` и `phalanx-runtime/src/state/sections/soa.ts`.
3. physics при restore добавляет `Interpolation` каждому телу, у которого он был при создании (правило transient из A6b.1).
4. Классы-обёртки компонентов physics удаляются, удобные методы становятся функциями-хелперами.
5. Убрать дубль `InterpolatedTransformSample` из ecs.
6. Сейв physics побайтно совпадает с голденами (`lastX/lastZ` и раньше не сохранялись).

### A6b.2b. Перевод abilities

1. `Attributes`, `ActiveEffects`, `GameplayTags` и компонент-владелец через `defineComponent` (объектный вид, где списки).
2. Компонент `AbilitySystem` переименовывается в `AbilityOwner` (утверждено). Имя `AbilitySystem` остаётся за сервисом (A6c).
3. `GameplayTags.save` сортирует теги.
4. Классы-обёртки компонентов abilities удаляются, удобные методы становятся функциями-хелперами.
5. Сейв abilities побайтно совпадает с голденами.

### A6b.2c. Удаление старого пути

1. Удаляются `createComponentTypeRegistry`, символы `*_COMPONENT_TYPE` (включая `PHYSICS_BODY_COMPONENT_TYPE`, `TRANSFORM_COMPONENT_TYPE`), `abilityComponentTypes`, базовый `SoAComponent` в старом виде, `registerComponentTypes` в `SystemRegistry`, старый `defineComponent` в runtime.
2. Убрать статический `SoAComponent._entityManager` (`useEntityManager`, `resetContext`). Хранилище находится через мир, переданный в `world.addComponent`/`world.getComponent`. `dispose()` одного мира не трогает другие. `WorldScope` удаляется целиком (экспорты runtime и `/advanced` тоже).
3. Тест: два мира вперемешку пишут в свои SoA-хранилища, закрытие одного не ломает другой.
4. Голдены те же.

## A6c. ecs: сервисы и query

1. Сервисы: `defineService<T>(name)`, `world.provide(key, impl)`, `ctx.getService(key)`, `ctx.tryGetService(key)`. Ключ сравнивается по ссылке. Ошибки:
   - повторный `provide` того же ключа;
   - `provide` другого ключа с уже занятым `name` (сообщение подсказывает про две копии пакета в сборке);
   - отсутствующий сервис: в сообщении `name` и список предоставленных сервисов.
2. physics и abilities в этом же PR минимально переходят на сервисы: `Physics = defineService<PhysicsWorld>('physics')`, `Abilities = defineService<AbilitySystem>('abilities')`. `PhysicsWorld.attach` и `createAbilitySystem` вызывают `provide` вместо записи в `world.context`. Удаляются `SystemContext.physics/.abilities`, геттеры в `GameSystem`, `IPhysicsWorld`, `IAbilitySystem`, неявное дописывание систем abilities в `SystemRegistry`.
3. Сервисы общаются через шину мира, прямой вызов через `getService`.
4. Query:
   - `world.query(A, B, ...)` (кортеж с выводом типов) и `world.queryAny(...)` (отсутствующие компоненты как `undefined`);
   - порядок по id, как сейчас (`SoAComponentStore.entityIds()` и индексы `EntityManager` уже отсортированы), голдены те же;
   - обход по снимку id, снятому в начале цикла. На каждом шаге сущность проверяется: удалённую или потерявшую компонент пропускаем. Созданные во время цикла в этом проходе не обходятся (записать в документации);
   - кортеж переиспользуется, сохранять его между итерациями нельзя;
   - для SoA query отдаёт индекс строки, чтобы горячие циклы читали typed arrays напрямую. `PhysicsSystem` оставляет прямой доступ к массивам;
   - индекс строки берётся на каждом шаге по id и действует только до следующего добавления или удаления в этом хранилище. `SoAComponentStore` удаляет через swap-and-pop: на место удалённой строки встаёт последняя, поэтому заранее посчитанные индексы после удаления внутри цикла указывают на чужие строки. Тест: удаление сущности впереди по обходу не портит данные оставшихся;
   - версии с `symbol[]` уходят в `/advanced`.
5. Тесты: порядок query, удаление и снятие компонента внутри цикла, создание внутри цикла, все ошибки сервисов. Фазы и их тесты — в A6d.

## A7. physics

1. `physics.attach(world)` регистрирует компоненты, системы, сервис и секцию сейва. `getSystems()` удаляется. Фаз ещё нет: они в A6d, после A8.
2. Две независимые настройки:
   - `collisionResponse: 'push' | 'impulse'` (есть; impulse использует chapaev);
   - `integrate: boolean` (по умолчанию true).
3. `integrate: false` — режим «только столкновения» (имя утверждено; `mode: 'full' | 'collisionsOnly'` не используем). Игра двигает сама, физика разводит. Совпадает с `CollisionSystem`:
   - 1 проход разрешения за тик (`subSteps` не применяется);
   - без трения, без `maxVelocity` и `worldBounds`;
   - сила расталкивания `overlap × pushStrength`, без умножения на restitution (у `PhysicsSystem` сейчас среднее restitution, по умолчанию 0.5 у тела, то есть вдвое слабее);
   - скорость от расталкивания не трогаем: как в текущем `CollisionSystem`, она пишется в `velocity` и не интегрируется в позицию (позицию меняет только разведение).
4. Порядок коммитов:
   1. реализация `integrate: false`;
   2. тесты `CollisionSystem` переносятся на `integrate: false` + `push` и совпадают побайтно по состоянию после каждого тика;
   3. только после этого `CollisionSystem` удаляется. Отличия, если остались, — в CHANGELOG.
5. Удаляются `setTickProvider`, `IPhysicsTickProvider`, `ExternalPhysicsTickProvider`: физику двигает только тик мира.
6. Системы обходят сущности через `world.query` с индексом строки (A6c.4).
7. Формат сейва physics не меняется.

## A8. abilities

1. `createAbilitySystem(world, config)` регистрирует компоненты, системы, сервис `Abilities` и секцию сейва. Фазы — в A6d.
2. Одно представление данных. Сейчас attributes, effects и tags живут и внутри компонента-владельца, и отдельными компонентами, getter'ы проверяют оба варианта. Оставить только отдельные компоненты, `AbilityOwner` хранит лишь своё. Если это меняет формат сейва — новый формат и регенерация голденов отдельным коммитом.
3. Системы эффектов на `world.queryAny`.
4. `releasePooledAbilityState` упростить: после п. 2 ветвления по двум представлениям уходят. Проверить на дубли с автосбросом пулов.
5. Формат сейва abilities не меняется, кроме случая из п. 2.
6. Компоненты присоединяются только через `world.addComponent(entity, Component, init)`. `createAbilitySystem` регистрирует `attach` / `remove` хуки: `world.addComponent(e, AbilityOwner, init)` создаёт все четыре компонента, `world.removeComponent(e, AbilityOwner)` удаляет все четыре, удаление `Attributes` / `ActiveEffects` / `GameplayTags` при наличии владельца бросает ошибку (с тестами). Фабрики пулов получают `(id, world)`, `world.createEntity()` сразу регистрирует сущность.

## A6d. ecs: фазы систем

Отдельный PR после A8. В A6c фазы не входят.

1. Фазы систем. Порядок систем — часть детерминизма, поэтому он задаётся явно:
   - фиксированный список фаз, например `input → abilities → physics → late` для tick и отдельный список для frame;
   - `world.addSystem(system, { phase, before?, after? })`. Внутри фазы порядок регистрации, `before/after` уточняют. Цикл ограничений даёт ошибку при `start()`;
   - после `start()` порядок заморожен, `addSystem` бросает ошибку;
   - у системы обязательное `name`; список имён по порядку входит в `configHash`, чтобы разный порядок у клиентов ловился сразу;
   - `registerSystems` удаляется (сейчас он заменяет списки целиком, повторный вызов теряет системы). `MatchRunner`, фикстуры, playground и integration переходят на `addSystem`;
   - physics и abilities, зарегистрированные в A7 и A8, переводятся на фазы: gravity перед системой физики в фазе `physics`, системы abilities в фазе `abilities`. Игра ставит свои системы в нужные фазы.
2. Тесты: порядок фаз и `before/after`, цикл ограничений, `addSystem` после `start()`, разный порядок систем меняет `configHash`.

## Изменения относительно прошлой версии плана

Четвёртая правка:

- Transient-компоненты приняты. Страж: tick-системы не принимают по ним решений, проверка хотя бы в dev-режиме.
- Фазы систем (бывший A6c.4) вынесены в отдельный PR A6d после A8.
- Переименование компонента `AbilitySystem` в `AbilityOwner` утверждено.
- A7.3: настройка называется `integrate: false`. Скорость от расталкивания не трогаем — как в текущем `CollisionSystem` (пишет в `velocity`, не интегрирует).

Третья правка:

- A6b.2 разделён на A6b.2a (physics), A6b.2b (abilities) и A6b.2c (удаление старого пути, статического контекста SoA и `WorldScope`).
- `lastX/lastZ` удаляются без замены: читателей у них нет. Transient-вид остаётся ради `Interpolation`.
- В query для SoA уточнено время жизни индекса строки (swap-and-pop при удалении).

Вторая правка:

- A6a разделён на A6a.1 (без работы при импорте, `globalEventBus`, `sideEffects: false`) и A6a.2 (счётчик id в мире, `createEntityWithId`).
- Статический контекст SoA и `WorldScope` удаляются в A6b.2: без статики конструктору компонента нужен мир, а это `world.addComponent` из A6b.
- `globalEventBus` — только лишний экспорт, шина уже у каждого мира своя.
- Для `integrate: false` добавлены открытые вопросы: судьба скорости от расталкивания и название настройки.

Первая правка:

- A6 разделён на A6a/A6b.1/A6b.2/A6c, чтобы монорепо оставалось зелёным: physics и abilities переходят на новые компоненты и сервисы в тех же PR, где удаляется старый API.
- Добавлено: аллокатор id и контекст SoA принадлежат миру; тест двух миров вперемешку.
- Добавлен transient-вид компонентов; `lastX/lastZ` решаются в A6b.2, а не в конце A7.
- Добавлены фазы систем и порядок систем в `configHash`; `registerSystems` удаляется.
- `integrate: false` описан по всем пяти расхождениям с `CollisionSystem`, удаление только после побайтного совпадения тестов.
- Компонент `AbilitySystem` → `AbilityOwner`; одно представление данных в abilities.
- Детерминированный сейв объектных компонентов, ошибка `save`/`load` при регистрации, понятные ошибки ключей сервисов, индекс строки в query для SoA, `sideEffects: false` и в ecs.
- Убран пункт про проверку phalanx-games: тестовая игра переписывается на новом API.
