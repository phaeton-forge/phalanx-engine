# План улучшения внешнего вида юнитов на formation grid

> Статус: предложение / план реализации  
> Проект: `abilities-playground` (Three.js)  
> Цель: сделать форму и границы юнитов четко читаемыми, ввести палитры команд (синяя / красная), использовать имеющиеся деревянные, металлические и напольные PBR-текстуры.

---

## 1. Что видно на скриншотах — диагноз текущего состояния

На приложенных скриншотах юниты выглядят как **плоские цветные пятна** на темном фоне:

- **Форма читается плохо.** Грани между гранями почти не различимы, особенно на `box` и `octahedron`.
- **Нет объема.** Материал `MeshStandardMaterial` с `roughness = 0.55`, `metalness = 0.05` выглядит как матовый пластик; отсутствуют тени от юнитов на землю и друг на друга.
- **Один цвет на всю команду.** Сейчас используется один глобальный цвет (`#3366FF` / `#FF3333`) для всех юнитов команды, материалов здоровья и линий сетки.
- **Сетка formation grid почти незаметна.** Линии сетки прозрачные (`opacity = 0.45`), подложки под ячейками нет.
- **Юниты "парят" над сеткой.** Нет визуальной связи с поверхностью (нет тени, нет основания/подставки).
- **Текстуры уже есть, но не используются.** В `abilities-playground/public/` лежат полные PBR-сеты деревянных материалов (`Wood076`, `Wood095`, `Wood026`, `Wood028`), два металлических набора (`metal-panel1`, `metal-panel2`), напольный орнаментальный набор (`floor/ornate_techno_grid_*`) и HDRI-окружение, но в коде `TextureLoader` не вызывается.

---

## 2. Цели преобразования

1. **Четкость формы и граней.** Любой юнит (сфера, куб, конус, октаэдр, volt) должен читаться с первого взгляда: видны ребра, грани, освещенная и затененная стороны.
2. **Палитры команд.** Красный игрок получает красно-оранжево-коричневую палитру, синий — синюю с оттенками стали и льда.
3. **Текстурное разнообразие.** Использовать деревянные PBR-текстуры как базу для корпуса и металлические панели (`metal-panel1`, `metal-panel2`) для брони/деталей, придавая им командный оттенок через tint.
4. **Связь с formation grid.** Юниты должны визуально "стоять" на сетке, а сетка должна быть более заметной и командно-цветной.
5. **Пол арены.** Заменить плоский серый пол на PBR-текстуру с орнаментом, осветлённую и затонированную в нейтральный цвет.
6. **Минимальные изменения архитектуры.** Не ломать ECS, не менять игровую логику, только визуальный слой.

---

## 3. Концепция визуального стиля

### 3.1. Общая идея: "деревянные фигурки с металлическими элементами"

Теперь, когда доступны и деревянные, и металлические PBR-наборы, предлагается стилистика **настольных тактических фишек, частично обшитых металлом**:

- Базовая фигурка выполнена из дерева и тонирована в цвет команды (как покрашенный лаком деревянный корпус).
- Тяжелые / боевые / футуристичные юниты (`box`, `octahedron`, `volt`) получают металлические пластины, болты, рамки или сопла из `metal-panel1` / `metal-panel2`.
- Границы и ребра читаются за счет контраста между деревом и металлом, скруглений (bevel), нормал-мап, направленного света и теней.

### 3.2. Палитры команд

Заменить одиночные цвета на палитры из 5 ключей. Пример:

**Синяя палитра (Team 0):**

| Роль | HEX | Назначение |
|------|-----|------------|
| `primary` | `#2563EB` | Основной цвет фигурки |
| `deep` | `#1E3A8A` | Тени, контур, темные участки |
| `steel` | `#60A5FA` | Блики, светлые грани |
| `ice` | `#93C5FD` | Emissive glow для магических юнитов |
| `neon` | `#00BFFF` | Аура, способности, вспышки |

**Красная палитра (Team 1):**

| Роль | HEX | Назначение |
|------|-----|------------|
| `primary` | `#DC2626` | Основной цвет фигурки |
| `deep` | `#7F1D1D` | Тени, контур, темные участки |
| `ember` | `#F87171` | Блики, светлые грани |
| `magma` | `#FB923C` | Emissive glow для магических юнитов |
| `flare` | `#FF4500` | Аура, способности, вспышки |

Палитра хранится в `src/config/constants.ts` и используется для:
- tint материала,
- цвета health bar,
- цвета grid lines,
- цвета aura ring,
- emissive glow для `volt` и `support`.

## 4. Технические предложения

### 4.1. Улучшение освещения и читаемости граней

Текущее освещение: `AmbientLight(0xffffff, 0.55)` + `DirectionalLight(0xffffff, 0.85)`.

Предлагается:

1. **Основной направленный свет (key light)** — оставить, но увеличить интенсивность до `1.2–1.5` и настроить угол так, чтобы создавать четкие тени.
2. **Включить тени:**
   - `renderer.shadowMap.enabled = true` (PCFSoftShadowMap).
   - `sun.castShadow = true`.
   - У юнитов включить `castShadow = true` и `receiveShadow = true`.
   - У земли `receiveShadow = true`.
3. **Заполняющий свет (fill light)** — добавить мягкий `HemisphereLight` снизу (цвет неба / цвет земли), чтобы тени не были полностью черными.
4. **Контровой свет (rim light)** — второй направленный свет с противоположной стороны, слабый (`0.3–0.5`), для выделения силуэта юнитов на фоне темной арены.
5. **HDRI-окружение** — загрузить `public/env/IndoorEnvironmentHDRI013_2K_HDR.exr` и назначить `scene.environment`, чтобы PBR-материалы получали реалистичные отражения (как уже сделано в `chapaev`).

Эффект: грани будут четко отделяться друг от друга за счет светотени и отражений.

### 4.2. Система материалов и текстур

Создать новый модуль `src/rendering/MaterialLibrary.ts` (или `src/units/UnitMaterialFactory.ts`) со следующими обязанностями:

1. **Предзагрузка текстур.**
   - Использовать `THREE.TextureLoader` для загрузки `BaseColor`, `NormalGL`, `Roughness`, `Metallic`, `AmbientOcclusion` карт.
   - Поддержать два типа PBR-наборов:
     - **Wood** — `Color`/`NormalGL`/`Roughness`/`AmbientOcclusion`.
     - **Metal panel** — `BaseColor`/`Normal_GL`/`Roughness`/`Metallic`/`AmbientOcclusion`.
   - Кешировать текстуры (не загружать по нескольку раз).
   - Устанавливать `colorSpace = THREE.SRGBColorSpace` для `BaseColor`/`Color` карт.
   - Для `Roughness`, `Metallic`, `AO` — `colorSpace = THREE.NoColorSpace`.

2. **Базовые материалы по типам юнитов (wood + metal).**
   Каждый юнит состоит из **основного тела** (дерево) и **металлических деталей**:

   | Юнит | Основной материал (body) | Металлические детали (trim) | Почему |
   |------|--------------------------|----------------------------|--------|
   | `sphere` | `Wood095` (bright-checker) | `metal-panel1` — обод / шипы | Легкий деревянный щит с металлическим ободом. |
   | `box` (cube) | `Wood076` (boards) | `metal-panel2` — броневые пластины, болты | Тяжелый танк в грязной броне. |
   | `cone` (support) | `Wood028` (deck) | `metal-panel1` — кольца / полосы | Маг/поддержка с полированными металлическими кольцами. |
   | `octahedron` (rocket) | `Wood026` (dark-checker) | `metal-panel2` — сопла, обшивка снаряда | Агрессивный снаряд в грязной металлической обшивке. |
   | `volt` | `metal-panel1` (body) + emissive glow | `metal-panel2` — катушки, проводники | Футуристический кастер с чистым металлом и неоном. |

3. **Многослойные материалы (multi-material mesh).**
   - Для юнитов, у которых есть и дерево, и металл, использовать `THREE.Mesh` с массивом материалов (`material: THREE.Material[]`) или группу дочерних мешей.
   - Пример: куб — `RoundedBoxGeometry` с материалом дерева + отдельные маленькие плейны/боксы для металлических пластин.
   - Металлические детали используют `metalnessMap` и `roughnessMap`, чтобы участки панели буквально выглядели металлическими.

4. **Применение палитры (tint).**
   - Для **деревянных частей**: в `MeshStandardMaterial` использовать свойство `color` для тонировки в `primary` цвет команды с множителем `0.6–0.8`, чтобы текстура дерева просвечивала.
   - Для **металлических частей**: использовать более слабый tint (`0.3–0.5`) или tint в `highlight`, чтобы металл сохранял свой холодный/теплый блеск, но все еще узнавался как часть команды.
   - Для `volt` и `support` — `emissive` по `glow` с интенсивностью `0.3–0.6`.

5. **Fallback.**
   - Если текстуры не загрузились, материал должен автоматически откатываться на процедурный `MeshStandardMaterial` с team color.
   - Для металлических деталей fallback — `MeshStandardMaterial({ color: 0x888888, metalness: 0.8, roughness: 0.4 })`.

6. **Кеширование материалов.**
   - Материалы кешировать по ключу `"${materialKey}_${teamId}"` (например, `"wood095_0"`, `"metalPanel1_1"`).
   - Это позволяет не создавать десятки одинаковых материалов и не дублировать загрузку текстур.

### 4.2.1. Централизованная загрузка ассетов с ретраем и лоадером

Сейчас в `abilities-playground` нет централизованного загрузчика текстур. Предлагается создать `src/core/AssetManager.ts`:

1. **Список ассетов.**
   - Описать все PBR-наборы в одном месте:
     - wood: `Wood076`, `Wood095`, `Wood026`, `Wood028`
     - metal: `metal-panel1`, `metal-panel2`
     - floor: `floor/ornate_techno_grid`
     - env: `env/IndoorEnvironmentHDRI013_2K_HDR.exr`

2. **Асинхронная загрузка с прогрессом.**
   - `AssetManager.loadAll()` возвращает `Promise` и сообщает прогресс (`loaded / total`).
   - Поддержка `THREE.TextureLoader` и `THREE.EXRLoader` (для HDRI).
   - Все текстуры загружаются до старта игры.

3. **Ретрай при ошибках.**
   - При `onError` автоматически повторять загрузку до `N` раз (например, 3) с экспоненциальной задержкой.
   - После исчерпания попыток — fallback на процедурные материалы / серый цвет, но игра не падает.

4. **Лоадер на экране.**
   - Пока `AssetManager` загружает текстуры, показывать DOM-лоадер с прогресс-баром.
   - Лоадер удаляется после завершения загрузки или перехода в fallback.
   - Пример UI: "Loading assets... 45%" + spinner.

5. **Кеширование.**
   - Загруженные `THREE.Texture` хранятся в `AssetManager` и выдаются по запросу.
   - `MaterialLibrary` не загружает текстуры сама, а запрашивает их у `AssetManager`.

Пример API:

```ts
// src/core/AssetManager.ts
export class AssetManager {
  async loadAll(onProgress: (loaded: number, total: number) => void): Promise<void>;
  getTexture(name: string): THREE.Texture | undefined;
  getEnvironment(): THREE.DataTexture | undefined;
  readonly isReady: boolean;
}
```

### 4.3. Улучшение геометрии юнитов

Принцип: **форма остаётся простой и читаемой**, но каждый юнит получает 2–4 узнаваемые детали из базовых примитивов (тор, цилиндр, конус, сфера, бокс). Никаких внешних моделей — только нативная Three.js геометрия.

#### 4.3.1. Общие улучшения для всех юнитов

1. **Скругленные ребра (bevel).**
   - Для `box` заменить `BoxGeometry` на `RoundedBoxGeometry` (из `three/examples/jsm/geometries/RoundedBoxGeometry`) с небольшим радиусом (`0.15–0.25` от размера).
   - Скругленные ребра отбрасывают характерные блики — форма читается значительно лучше.

2. **Подставка / основание (base).**
   - Добавить каждому юниту тонкую цилиндрическую или квадратную подставку того же team color, но темнее (`deep`).
   - Подставка визуально "приземляет" юнита на сетку и улучшает читаемость силуэта.

3. **Различимость масштабов.**
   - Сейчас `cube size = 5`, `sphere size = 2` — куб визуально огромен. Предлагается привести размеры к единой визуальной шкале (например, условный "occupied cell radius"), чтобы разница в размерах была заметна, но не диспропорциональна.

#### 4.3.2. Геометрия по типам юнитов

**`sphere` — "Щитовик / Боец"**
- База: сфера.
- **Экваториальный обод** — тонкий тор вокруг сферы (как обруч или ремень брони), `metal-panel1`.
- **Шип / антенна сверху** — маленький цилиндр + сфера на конце, team `steel` / `ember`.
- **Подставка** — низкий цилиндр чуть шире сферы, team `deep`.

**`box` — "Танк / Тяжеловес"**
- База: `RoundedBoxGeometry` (скруглённые ребра).
- **Броневые пластины по углам** — 8 маленьких выступающих боксов или цилиндров в углах, `metal-panel2`.
- **Болты** — крошечные сферы в центре каждой грани, `metal-panel1`.
- **Ребра жёсткости** — тонкие выступающие полосы по вертикальным рёбрам, `metal-panel2`.
- **Подставка** — массивный низкий цилиндр или скруглённый бокс, team `deep`.

**`cone` — "Поддержка / Маг"**
- База: конус (форма мантии / балахона).
- **Пояс** — тор вокруг середины конуса, `metal-panel1`.
- **Кристалл / символ сверху** — маленький октаэдр или сфера с `emissive` glow по `ice` / `magma`.
- **Рукава** — два коротких цилиндра по бокам от середины конуса, team `primary`.
- **Подставка** — тонкое кольцо (тор) у основания, team `deep`.

**`octahedron` — "Ракета / Стрелок"**
- База: октаэдр (снаряд / кристалл).
- **Стабилизатор** — тор вокруг центра октаэдра, `metal-panel1`.
- **Сопла снизу** — 3–4 маленьких цилиндра или конуса, направленных вниз, `metal-panel2`.
- **Плавники** — 4 тонких бокса, торчащих из центра под углом, team `deep`.
- **Подставка** — небольшая пусковая платформа (квадратная призма), team `deep`.

**`volt` — "Электро-кастер"**
- База: оставить текущую композицию (ядро, тор, сфера), но улучшить.
- **Дополнительные кольца** — ещё 1–2 тороидальных кольца вокруг ядра под разными углами, `metal-panel2`.
- **Шаровые молнии** — 3–4 маленькие сферы, летающие вокруг ядра на небольшом расстоянии, `emissive` по `ice` / `magma`.
- **Кристаллическое ядро** — заменить октаэдр на `IcosahedronGeometry` для более технологичного вида, team `primary` + emissive glow.
- **Подставка** — тонкое кольцо-стабилизатор у основания, `metal-panel1`.

### 4.4. Контуры и подсветка

1. **Тонкий контур (outline).**
   - Для улучшения читаемости на темном фоне добавить второй pass: слегка увеличенная копия меша с `Material({ color: deepColor, side: THREE.BackSide })`.
   - Альтернатива: использовать `OutlineEffect` из `three/examples/jsm/effects/OutlineEffect`, но это более дорогой вариант.
   - Контур тонкий (`0.05–0.1` мировых единиц), темный (`deep`), чтобы не превращаться в мультяшную обводку.

2. **Rim / emissive highlight.**
   - Для магических юнитов (`volt`, `support`) добавить `emissive` по цвету `ice` / `magma` с низкой интенсивностью (`0.2–0.4`).
   - Это визуально отделит их от обычных юнитов.

3. **Health bar.**
   - Фон сделать темнее (`#111111`), заполнение — `primary` цвет команды.
   - Добавить тонкую рамку (`deep`) для читаемости.

### 4.5. Formation grid — улучшение сетки

1. **Подсветка ячеек.**
   - Добавить под каждой ячейкой полупрозрачный `PlaneGeometry` с team-tinted цветом (`primary`, `opacity = 0.08–0.12`).
   - Это визуально "впишет" сетку в арену и сделает ее заметнее.

2. **Усиление линий сетки.**
   - Увеличить `opacity` линий с `0.45` до `0.7–0.85`.
   - Использовать не сплошной `primary`, а градацию: основные линии — `primary`, центральная / spawn-линия — `neon` / `flare`.

3. **Hover-эффект.**
   - При наведении на ячейку подсвечивать ее цветом `steel` / `ember` с `opacity = 0.25`.
   - Ghost-юнит при размещении оставить, но использовать более читаемый материал (полупрозрачный + tint).

4. **Связь юнита с ячейкой.**
   - Добавить легкую тень от юнита на сетку (через `castShadow` + `receiveShadow` на pick plane / ground).

### 4.6. Пол арены

Заменить плоский серый пол (`arenaParams.groundColor`) на PBR-материал с текстурой `floor/ornate_techno_grid_*`:

1. **Текстурный набор.**
   - `BaseColor` — основной орнамент.
   - `Normal_GL` — микрорельеф линий орнамента.
   - `Roughness` — вариации шероховатости.
   - `Metallic` — металлические элементы орнамента.
   - `AO` — затенение в углублениях.

2. **Осветление и тонировка.**
   - Исходная текстура очень тёмная, поэтому использовать `material.color` для осветления и тонировки.
   - Рекомендуемый `color: new THREE.Color(0.55, 0.55, 0.6)` — осветляет в ~2 раза и делает оттенок холоднее.
   - Итоговая средняя яркость пола должна быть в районе `#5a5a62` — `#6a6a72`.

3. **Параметры материала.**
   ```ts
   {
     map: floorBaseColor,
     normalMap: floorNormal,
     roughnessMap: floorRoughness,
     metalnessMap: floorMetallic,
     aoMap: floorAO,
     color: new THREE.Color(0.55, 0.55, 0.6),
     roughness: 0.8,
     metalness: 0.3,
     envMapIntensity: 0.4,
   }
   ```

4. **Тайлинг.**
   - Подобрать `texture.repeat.set(repeatX, repeatY)` так, чтобы орнамент не был слишком крупным.
   - Для арены `90 × 200` рекомендуется `repeat.set(6, 12)` — `8, 16` в зависимости от разрешения текстуры.

5. **Читаемость юнитов.**
   - Орнамент достаточно активный, поэтому:
     - `roughness` высокий (`0.75–0.85`), чтобы не было сильных бликов.
     - `metalness` умеренный (`0.2–0.4`), чтобы металлические линии слегка выделялись, но не отвлекали.
   - При необходимости добавить лёгкий туман (`scene.fog`), чтобы дальние участки пола слегка затенялись.

### 5.3. Пример фабрики материалов

```ts
// src/rendering/MaterialLibrary.ts

/** Wood body material — tinted by team primary color. */
export function getWoodMaterial(
  woodSet: WoodSetId,
  teamId: TeamId
): THREE.MeshStandardMaterial {
  const palette = teamPalettes[teamId];
  const textures = getOrLoadWoodTextures(woodSet);
  const key = `wood:${woodSet}:${teamId}`;

  if (materialCache.has(key)) return materialCache.get(key)!;

  const mat = new THREE.MeshStandardMaterial({
    map: textures.color,
    normalMap: textures.normal,
    roughnessMap: textures.roughness,
    aoMap: textures.ao,
    color: new THREE.Color(palette.primary).multiplyScalar(0.7),
    roughness: 0.65,
    metalness: 0.05,
    envMapIntensity: 0.7,
  });

  materialCache.set(key, mat);
  return mat;
}

/** Metal trim material — less tinted, uses Metallic map. */
export function getMetalTrimMaterial(
  panelSet: MetalPanelId,
  teamId: TeamId
): THREE.MeshStandardMaterial {
  const palette = teamPalettes[teamId];
  const textures = getOrLoadMetalTextures(panelSet);
  const key = `metal:${panelSet}:${teamId}`;

  if (materialCache.has(key)) return materialCache.get(key)!;

  const mat = new THREE.MeshStandardMaterial({
    map: textures.baseColor,
    normalMap: textures.normal,
    roughnessMap: textures.roughness,
    metalnessMap: textures.metallic,
    aoMap: textures.ao,
    color: new THREE.Color(palette.highlight).multiplyScalar(0.4),
    roughness: 0.5,
    metalness: 0.9, // Base value; Metallic map modulates per-pixel.
    envMapIntensity: 1.0,
  });

  materialCache.set(key, mat);
  return mat;
}
```

## 7. Ожидаемый результат

- Юниты четко читаются по форме: видны грани, ребра, освещенные и затененные стороны.
- Каждая команда имеет узнаваемую цветовую палитру: синие оттенки у одной, красно-оранжевые у другой.
- Деревянные текстуры придают объем и тактильность, металлические панели — контрастные блики и "бронированные" детали.
- Командный tint не перекрывает текстуры, а гармонично их окрашивает.
- Пол арены выглядит как технологичный металлический настил с орнаментом, при этом не отвлекает от юнитов.
- Formation grid выглядит как игровое поле с подсвеченными ячейками, а не как полупрозрачная сетка.
- Юниты визуально связаны с поверхностью через тени и подставки.
- Пользователь видит лоадер во время загрузки PBR-ассетов, а при ошибках игра продолжает работать на fallback-материалах.

## 8. Риски и как их сгладить

| Риск | Митигация |
|------|-----------|
| Падение FPS из-за теней + PBR + HDRI | Сделать настройки качества; возможность отключить тени/HDRI на слабых устройствах. |
| Текстуры не загрузятся / долгая загрузка | Fallback на процедурные материалы; ретрай с задержкой; лоадер с таймаутом. |
| Слишком мультяшный outline | Делать контур тонким и темным, почти незаметным — только для читаемости силуэта. |
| Tint перекрывает текстуру дерева | Использовать `color.multiplyScalar(0.6–0.8)`, чтобы текстура просвечивала. |
| Мобильные устройства не потянут EXR | Для мобильных использовать tonemapped JPG вместо EXR или отключать environment map. |
| Много материалов на одном юните увеличивает draw calls | Объединять металлические детали в одну геометрию с multi-material или минимизировать количество отдельных мешей. |
| Metal-panel выглядит слишком "чистым" / не вписывается | Использовать `metal-panel2` (dirty) для боевых юнитов и регулировать roughness/metalness через карты. |
| Floor-орнамент слишком "шумный" | Увеличить roughness, осветлить/затонировать color, использовать fog для дальних планов. |
| AssetManager блокирует старт при ошибке | Таймаут + fallback: после N ретраев стартовать с процедурными материалами. |

## 9. Вопросы для уточнения перед стартом

1. **Стиль:** Нужен ли четкий "outline" вокруг юнитов или лучше обойтись освещением + тенями?
2. **Текстуры:** Какой wood-сет и какой metal-panel назначить каждому типу юнита? (см. предложение в п. 4.2)
3. **Соотношение дерева и металла:** Хотите, чтобы юниты были в основном деревянными с металлическими деталями, или некоторые юниты полностью металлические?
4. **Палитра:** Устраивают ли предложенные HEX-цвета, или есть корпоративные/игровые цвета?
5. **Производительность:** Есть ли целевой минимум FPS / устройства, на которых нужно тестировать?
6. **HDRI:** Использовать EXR из `public/env/` или ограничиться tonemapped JPG для скорости загрузки?
7. **Formation grid:** Нужна ли анимация появления / перемещения юнитов на сетке?
8. **Лоадер:** Какой стиль лоадера предпочтителен — простой прогресс-бар, спиннер, или что-то в стиле игры?
9. **Floor:** Устраивает ли предложенная тонировка `color = (0.55, 0.55, 0.6)` и тайлинг `repeat.set(6, 12)`?
